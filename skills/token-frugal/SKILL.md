# 省 token 操作规范

## 0. 一条公式

```
成本 ≈ 进入上下文的体积 × 它后面还剩多少步
```

读进来只是起点，**步数才是乘数**。任何优化都落在「减小体积」或「减少步数」上，其余都是折扣。

**优先级：先砍体积，再砍步数。** 为省一步而整读是净亏——实测同一任务，整读 1 次（56,319 字符 / 1 步）比窄读 1 次加 3 次定位（5,099 字符 / 4 步）贵约 6 倍：省下的字符远大于多花的步数。

本机实测（`opencode.db` 全量）的分布，决定优先级：

| 成分 | 占 conversation |
| --- | --- |
| 工具输出（read / bash / grep） | 54.5%，`read` 单项 30.7% |
| 附加文件 | 24.0% |
| 工具调用参数 | 13.5% |
| 助手正文 | 4.3% |
| 用户消息 | 2.3% |

结论：**只管工具输出就够了**，聊天气泡再长也不是问题。

两个已经验证过的比例，用来估账：

- 代码类内容约 **2.1 字符/token**（Java/XML 混合），英文文档约 3.5。
- 本机最大会话 1,652 步、473M prompt tokens，命中率 96.5%，实付 $4.96，不缓存要 $72。

## 1. 先度量，再优化

脚本随 skill 提供：`scripts/session-cost.py`。

```bash
# 最近一个会话
python ~/.agents/skills/token-frugal/scripts/session-cost.py
# 指定会话
python .../session-cost.py ses_xxx
# 会话排行，找最贵的
python .../session-cost.py --top 10
# 换模型价目（输入 / 输出 / 缓存命中，每百万 token）
python .../session-cost.py ses_xxx --prices 0.15 0.6 0.003
```

输出：步数、prompt 总量、命中率、实付与「完全不缓存」对比、以及最大的 5 条工具输出及其上界占比。
回答「这个会话多贵」时直接跑它，不要凭印象估。

## 2. 读文件：先定位，再窄读

1. 先 `grep` / `glob` / `ast_grep_search` 拿到行号或路径，不要先 `read` 整个文件。
2. `read` 必须带 `offset` / `limit`，一次 100–300 行；需要第二段再读第二段。
3. 同一个文件已经读过且没改过，不要重复读；改用记忆里的结论或 `ctx_search`。
4. 「看一下项目结构」用 `glob` 的路径清单，不是逐个读文件。
5. 大文件（>800 行）默认只读：类声明 + 目标方法 ±40 行。

单次 `read` 的代价参考：36,610 字符 ≈ 15,400 tokens ≈ 之后每一步都在付这笔钱。

实测反证（2026-10-28，1,791 行 / 65KB 的 Java 文件，问其中第 1012 行的方法）：不加载本 skill 时，模型一次裸 `read` 吐出 **56,319 字符 / 1,447 行**，且被截断——目标方法之后的 344 行根本没读到，又贵又不全；要求先定位后，读回 **5,099 字符 / 120 行**，正好命中目标方法。裸读不是省事，是双输。

## 3. 命令输出：先收窄，再执行

1. 编译/构建一律静默：`mvn -q`、`gradle -q`、`npm --silent`。
2. 输出强制截断：PowerShell `| Select-Object -First 40` / `-Last 40`；bash `| head -40` / `| tail -40`。
3. `Select-String` 过滤后仍可能几万字符，必须再接 `Select-Object -First N`。
4. 大输出写文件再针对性读：`> out.log`，然后 `grep` 它或 `read` 指定区间。
5. 只要「成功/失败」的地方，只输出 exit code 或最后一行。
6. 禁止 `cat` 整个大文件 / 整个配置；用 `grep -n` 取目标行。
7. 网页文档优先 context7 取片段，`webfetch` 整页是最后手段（实测一条 31,458 字符）。

本机最贵的 5 条输出全是 `bash`，合计占该会话全部 prompt 的 28.4%（上界）；字符数超 30k 的输出总共只有 5 条。

## 4. 步数：能合就合

1. 互不依赖的调用**放进同一条消息**（并行）。一次并行 4 个工具只算 1 步，分 4 步就是 4 次全量 prompt。
2. 不要用「试探性单次调用」摸路，先想清楚要什么再发。
3. 拆子任务前评估：多一轮的 prompt 成本是否小于收益。
4. 一轮里工具调用几次就有几个 step，各算各的账。

## 5. 复用：别重新发现

1. 结论写进 `ctx_memory`（项目事实）或 `ctx_note`（待办），下次直接读。
2. 查历史用 `ctx_search`，不要重新读文件验证已记录的事实。
3. 已有 archify 图 / 文档能回答的，不要再跑一遍代码。
4. 同一项目的连续任务留在同一会话（缓存前缀可复用）；换任务才开新会话。

## 6. 隔离：脏活丢给子代理

1. 需要扫 ≥3 个文件、或产物大概率被丢弃的探索，交给 `explorer` / `explore` 子代理。
2. 子会话上下文不回流，只回结论；这是唯一能把「读过的东西」清零的手段。
3. 指令里写明「只回结论 + 关键 file:line」，否则它会把原文搬回来。
4. 一次一个明确问题，任务保持小。

## 7. 回收：主动扔，别等阈值

1. 用完的大输出立刻 `ctx_reduce` 标记；队列化、缓存安全，不会抖动。
2. magic-context 的自动兜底是**按年龄**淘汰，不是按体积；刚读进来的 5 万字符不会被自动清掉。
3. 老历史用 `/ctx-wrapup N` 压成摘要，保留最新 N 条原文。
4. `execute_threshold_percentage` 默认 65%（窗口的 65%，输出预留已先扣除）；长任务想早点压就调低。
5. `caveman_text_compression` 只压你我文本，**不压工具输出**，别指望它救场。

## 8. 阈值线：什么时候必须动手

| 指标 | 警戒线 | 动作 |
| --- | --- | --- |
| 单条工具输出 | > 20,000 字符 | 立即 `ctx_reduce` |
| 会话步数 | > 30 步且 prompt > 100k | 开始逐条标记过期输出 |
| 窗口占用 | > 50% | `/ctx-wrapup` 或切子代理 |
| 单轮工具调用 | > 6 个 | 检查是否该拆子代理或复用结论 |
| 单步 prompt 环比 | 涨 > 30k | 回看这一步读了什么 |

## 9. 工具速查（省 token 的用法）

| 工具 | 用法要点 |
| --- | --- |
| `read` | 必带 `offset` / `limit`；不要裸读 |
| `grep` | 先定位，输出 file:line 即可 |
| `glob` | 只拿路径清单，判断结构用它 |
| `ast_grep_search` | 结构化定位，替代「通读再找」 |
| `shell` | `-q` + 尾部截断；大输出写文件 |
| `webfetch` | 最后手段；优先 context7 |
| `subagent` | 多文件探索的唯一清零手段 |
| `ctx_reduce` | 用完即标记，不用等 |
| `ctx_search` | 查历史结论，别重跑调查 |
| `ctx_expand` | 只在需要原文时用，它会整块拉回 |
| `ctx_memory` / `ctx_note` | 结论落盘，跨会话复用 |
| `edit` | 局部改；`write` 只用于新建或整体替换 |
| `archify` / 内嵌页 | 用图替代长段文字说明 |

## 10. 场景配方

**A. 代码调研（「这个功能怎么实现的」）**
`grep` 关键符号 → 3–5 处 file:line → `read` 每处 ±40 行 → 文件数超 5 交给 `explorer` → 结论写 `ctx_note`。

**B. Bug 排查**
先读报错原文定位到 1–3 个文件 → `read` 目标方法 → 复现命令加截断 → 不整库 `grep` 后全量输出。

**C. 改代码 / 重构**
`read` 目标方法 → `edit` 局部替换 → 测试命令 `-q` + 只看尾部失败摘要。

**D. 写文档 / 方案**
先立骨架 → 需要事实时窄读 → 不把整文件搬进正文 → 成品写文件给路径。

**E. 长任务（>30 步）**
每 10 步跑一次 `session-cost.py` 看 prompt 增速；到 50% 窗口执行 `/ctx-wrapup`。

## 11. 反模式清单

| 反模式 | 代价 | 改法 |
| --- | --- | --- |
| 先 `read` 整个文件再找 | 单次上万 token，且永久留在上下文 | `grep` → 窄读 |
| `mvn` / `npm` 不带 `-q` | 4 万字符级别 | `-q` + 尾部截断 |
| `Select-String` 后不截断 | 5 万字符 | `Select-Object -First 30` |
| `webfetch` 整页文档 | 1–3 万字符 | context7 取片段 |
| 大段内容贴进对话 | 永久占用 | 写文件，给路径 |
| 单次试探调用摸路 | 每步一次全量 prompt | 一次想清楚，并行发 |
| 反复读同一文件 | 重复付费 | 记进 memory / 用结论 |
| `write` 重写整个文件 | 新旧全文都进上下文 | `edit` 只改差异 |

## 12. 动手前自检

1. 这次要读的东西，能不能先定位到 200 行以内？
2. 这个命令的输出，我只需要哪一段？截断写了吗？
3. 这几个调用能合成一条消息并行吗？
4. 这个结论以前记过吗？要不要先 `ctx_search`？
5. 这轮探索的产物会留下来吗？会的话交给子代理。
